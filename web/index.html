The core idea

Exit code is not proof.

A process can exit successfully while producing the wrong result. Agent Proof checks observable outcomes instead of trusting a success message.

Understand the lifecycle

What the tool actually verifies

Each run records process details, before/after checks, recovery status, classification, and a digest over the proof structure.

01 / SNAPSHOT

Observe before

For configured changed-file checks, record the initial file state before execution.

02 / EXECUTE

Run the command

Execute the configured process with a timeout and capture exit status, stdout, stderr, and duration.

03 / VERIFY

Check outcomes

Check files, changed files, shell predicates, HTTP status, Git state, and configured environment values.

04 / CLASSIFY

Detect false success

A zero exit code is not enough when acceptance checks fail. Timeouts and failed execution receive distinct classifications.

05 / RECOVER

Attempt recovery

If configured, run the recovery command and repeat the checks. Recovery is only successful when the checks pass.

06 / RECORD

Write evidence

Save proof JSON, supporting logs, checkpoints, and a SHA-256 digest that verify-proof can recompute.

Run the real engine

From clone to verified receipt

Requires Go 1.22+ and a shell. Run these commands in a trusted local working directory.

Get the source

Clone the public repository and enter its directory.

Run tests

Execute the Go unit tests and build the CLI binary.

Generate evidence

Run a sample spec, inspect proof.json, then verify its digest.

git clone https://github.com/juliushill42/agent-proof.git
cd agent-proof
go test ./...
go build -o ./bin/agent-proof ./cmd/agent-proof
./bin/agent-proof chaos fake-success --evidence .agent-proof/demo
./bin/agent-proof run --spec spec.example.json --evidence .agent-proof/runs
./bin/agent-proof list --evidence .agent-proof/runs
# Verify the proof.json path printed by the run command:
./bin/agent-proof verify-proof .agent-proof/runs/<RUN_ID>/proof.json

The chaos command intentionally detects expected failures for fake-success, hung-agent, and partial-execution. Detecting the expected failure is a successful test outcome; it is not a PASS result for that simulated agent run.
